# 产品方向与趣味性诊断

> 本文记录一次关于「难得读书 / mybook」的产品复盘：客观诊断当前形态的问题，
> 并给出从「工具」走向「游戏」的三个方向与最小可玩版本（MVP）方案。
> 写给未来的自己回看——这里记录的是**为什么这么想**，不只是**做了什么**。

---

## 一、客观诊断：趣味性不足 + 工具属性过强

### 结构性矛盾
一路以来的每一次优化（祛魅软机制、砍自造伏笔、锁因果、逼极限、价值轴精密建模），
**都在提升「测量的严谨性」，但严谨性和趣味性在这个产品里是负相关的。**

| 追求的 | 实际效果 | 趣味代价 |
|---|---|---|
| 三选项等权、都痛、无标准答案 | 测得准 | 玩家每次都要「纠结做题」，累 |
| 因果自洽、锁既定事实 | 逻辑严谨 | 没了「我的选择能改变世界」的爽感 |
| 忠于原著锚点 | 不跑偏 | 可预测、惊喜少 |
| 价值轴/元轴/DNA 精密建模 | 报告专业 | 玩家玩时根本感觉不到，只在结算页看到一堆分析 |

### 结论
当前形态 ≈ **一个包着叙事皮的价值观测评工具**。
内核是 MBTI/性格测试那类「输入选择 → 输出分析报告」，只是换了古典文学的壳。
这类产品的宿命：**测一次很新鲜，测完就没有再玩的理由**——工具是用完即走的，不是游戏。

---

## 二、「测价值观」这种玩法到底有没有意思？分三种情况

1. **单人玩、测完给报告（现状）**：趣味天花板很低。
   乐趣 90% 在「看结果那一刻」，过程（做题）是成本不是乐趣。
   把过程做得再精致，玩家也是「为了看报告忍受做题」。→ 这就是「工具属性强」的来源。

2. **多人玩（方向对）**：乐趣从「自我认知」变成「社交比较」时会指数级放大。
   人对「我 vs 别人」的兴趣远大于「我是谁」。同一个困境，你和朋友选得不同，
   那个**差异本身**就是话题、就是乐趣。这是从工具变成游戏的关键跃迁。
   ⚠️ 但当前产品完全没有多人/对比机制（只有单向炫耀式的「分享结果链接」）。

3. **多人但仍只是「各测各的摆一起看」**：还是趣味不足，只是把单人的无聊 ×N。
   真正有意思的多人，是让「价值观差异」产生**互动/冲突/合作**。

---

## 三、出路：换趣味引擎（而非继续优化测量精度）

| 方向 | 玩法 | 趣味来源 | 改动量 | 评价 |
|---|---|---|---|---|
| **A 同题对赌**（社交比较） | 和朋友玩同一角色同一困境，互看选择 + 互猜对方会怎么选 | 「我居然猜错了我最好的朋友」——把价值观差异变成社交货币 | 中（有现成 share-codec 地基） | **投入产出比最高，推荐先做** |
| **B 多人共演一个角色**（协作/冲突） | 3 人分别扮一个角色身边的不同声音，一个困境投票/博弈/互相说服 | 人和人的博弈，而不是人和 AI 做题 | 大 | 最有趣但工程量最大 |
| **C 养成/连载**（留在单人） | 同一角色多章连载，选择跨局累积成独一无二的人格档案 | 追更 + 养成的沉没成本 | 中 | 能救工具属性，救不了社交趣味 |

**判断**：A 直击「多人这样玩有意思」，且改动可控，作为下一步首选。

## 四、MVP：零账号、零数据库的「异步对比」

### 要验证的唯一核心假设
> 「看到我和另一个人在同一个困境上的选择差异」——这件事到底有没有趣味、值不值得分享？

### 关键洞察：验证它不需要真·多人在线
不需要两人同时在线、不需要账号、不需要数据库。
靠一件事就够：**把「出题人的选择」编码进分享链接**（纯前端 URL 参数）。
代码里已有 `share-codec`（WorldState ↔ URL 编码）作为现成地基。

### 最小闭环
```
① 你玩完某角色一局（如慕容复）
   → 你的每一步选择编码进分享链接（纯前端，无后端）
② 把链接发给朋友：「你也来当慕容复，看看你跟我像不像」
③ 朋友打开链接 → 玩同一角色、同一批困境
   → 每做一次选择前，先让他猜「你觉得出题人会怎么选？」，再选他自己的
④ 朋友玩完 → 结算页对比：
   - 逐幕选择差异
   - 「他 5 个困境里有 3 个跟你不一样」
   - 「他以为你会自保，其实你选了牺牲」
   → 这个差异报告 = 全部乐趣所在
```

### 为什么这样最符合「最小可玩」
| | 真·多人在线 | 异步对比 MVP |
|---|---|---|
| 账号系统 | 必须 | **不要** |
| 数据库 | 必须 | **不要** |
| 两人同时在线 | 必须 | **不要**（谁方便谁玩） |
| 验证「差异有没有趣」 | 能 | **同样能** |
| 工程量 | 几周 | **一轮出雏形** |

**先用最轻的方式验证最核心的假设**：若朋友间传链接、比差异确实上头、自发传播，
再上账号/排行榜/多人房间才值得。否则账号系统做了也是白做。

### MVP 里最核心的机制：「猜 TA + 对比差异」
朋友玩时先猜出题人的选择、再做自己的选，结算页展示「猜中率 + 逐幕差异」。
这一个点就足够产生「我居然不懂我朋友 / 我们价值观差这么多」的社交乐趣。

### 待定的小决策（动手前对齐）
1. 对比载体：用现有分享链接（URL 编码），MVP 不引入数据库存档。
2. 「猜 TA」是否进 MVP：它是趣味放大器，但多一层交互。（倾向：进，因为它是 A 方向的灵魂）

## 五、给未来自己的提醒（方法论）

- **不要再无限优化生成质量**。决定这个产品死活的问题是「有没有人愿意反复玩」，
  而这个问题此前一次都没被验证过。严谨用错了地方 = 在优化一个可能方向就错了的东西。
- **先验证方向，再打磨内核**。MVP 的目的不是「做得好」，是「用最小成本证明方向对不对」。
- 做减法 > 做加法：能砍掉「看似有用其实无效」的机制，比不断堆功能更重要。

## 六、命名决策

- **正式应用名**：`测测你的价值倾向`（Eazo 平台上的 App 名，诚实的自我定位：承认内核是价值观测评工具，名实相符、好传播，自带「测测你的X」社交句式）。
- **首页大标题**：`假如你是Ta`（保留「代入名著角色」这个差异化钩子与悬念感，短、顺口）。
- **首页副标题**：`附身名著角色 / 测测你的价值观`（把完整价值主张讲清：代入 + 测评）。
- 演进过程：`难得读书/mybook`（卖叙事体验）→ 意识到内核其实是测评工具 → 短名候选（换你来选/他是你吗/假如你是他…）→ 定为「假如你是Ta」当首页标题 + 「测测你的价值倾向」当正式应用名。

## 七、技术可行性结论（真要做异步对比 MVP 时从哪下手）

- 现有 `src/lib/reader/share-codec.ts` 已能把 `WorldState`、`book+character` 编码进 URL
  （`buildAgentStoryShareUrl` / `buildAgentResultShareUrl` / `encodeAgentState`）。
- `src/app/page.tsx` 已有 `?mode=agent-story`（打开链接从头玩同角色）、`?mode=agent-result`、
  `?mode=agent-compare` 等 URL 入口的解析逻辑。
- **结论**：异步对比「用分享链接当信使」这条路，地基是现成的。真要做时主要缺的是这一层：
  ① 记录出题人**逐幕的困境与选择**（不只是最终 WorldState，要能让朋友复现同一批困境）；
  ② 朋友玩时的「猜 TA」交互；③「猜中率 + 逐幕差异」的对比结算页。
  可复用现有 `agent-compare-page.tsx`（极压对比页）的双轨对照 UI 作为对比结算的起点。
